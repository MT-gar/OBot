# 私人云电脑平台：从当前 MVP 到可交接、可恢复的私人电脑

更新：2026-11-21（Asia/Shanghai）。本路线依据[差异化构思](../差异化.md)、现有代码与已取得的验证记录调整。状态分为“已有本地验证”“已实现、待真实集成验收”和“待开发”；规划中的能力不计为完成。

## 1. 当前结论与开发主线

**当前处于 P1A 基础 MVP 收口。** WSL 的固定桌面演示和宿主 ACP 文本已有实机记录。下一步接通 Compose 中的 ACP 应用入口，并修正连续启动任务时出现的 409。租约失联保护可同步开发。完整的真实工具任务、分离环境恢复和隔离仍待验收。

接下来的顺序是：

1. 把现有 ACP、审批、桌面控制、持久化和隔离接成可重复验证的完整任务。
2. 完成“AI 工作 → 人接管并私人操作 → 在新状态下重新委派”的最小产品闭环。
3. 增加文件试做、差异、选择性接受、恢复点及真实恢复演练。
4. 在上述规则稳定后，减少重复审批，增加待办箱和日常使用能力。
5. 最后完成私人服务器部署、迁移和开源发布，再评估团队与生态。

差异化优先打磨三件事：**登录时可关闭 AI 观察、接管后可重新委派、AI 修改可逐项验收。** 持久目录和远程桌面是这些体验的基础。第一版继续限定单 owner、单台 Linux 电脑、一个活跃桌面输入者；开发和验收先在本地 WSL/Linux 完成。

本次调整不启动远程部署，也不把 Oracle 配额、Arm 兼容、更多 Agent 或前端框架迁移作为当前前置条件。原来从零起步的累计工期已不适用；后续按退出门槛推进，P1A 完成后再估算后续迭代。

## 3. 技术与产品边界

沿用当前原生 JavaScript/ES modules、Node 内置 HTTP/SSE/WebSocket、noVNC、Xvfb/Openbox/Chromium，以及 control/desktop/egress 分离结构。现有文件化控制状态先满足单 owner、单活跃 Run；只有出现明确的事务、查询或并发需求时再迁移数据库。React/TypeScript、数据库重写和通用插件框架不进入 P1 的关键路径。

当前主执行路径选用真实 DSH ACP。已验收的 WSL 独立运行时是 Node 24.22.3 和 DSH 0.2.2-rc.3；不能把 P0 的 Node 22 环境直接视为该运行时。由控制进程拥有 ACP 子进程、模型密钥、临时任务目录、预算策略和受限 MCP 能力；桌面不得获得模型/owner 凭据或云管理权限。保留原生 DSH 执行器，通过实际工具清单和服务端能力桥限制操作。

已有直连 Responses 实现保留其回归价值，但不作为 ACP 出错后的隐式降级路径。供应商拒绝、用量不明和工具失败必须如实报告，不伪装客户端、不绕过限制、不自动重复外部操作。

继续禁止向 Agent 开放任意 shell、任意 JavaScript 求值、Docker socket 或云管理员能力。对于通用 GUI，服务端无法仅凭坐标承诺“绝不会发信/付款”；第一批验收使用公开资料和固定测试站点，真实敏感提交继续由人处理。

## 4. P1A：把现有基础 MVP 验收收口（当前）

这一阶段补齐启动、连续运行和桌面撤权，再在同一套本地配置上做真实任务验收。A1、A2 的连续运行修复以及 A3 的 runner 租约开发可并行。

### A1 统一 ACP 启动、配置和诊断

- 复用已有的 ACP 镜像。在默认开发入口中，让 `build` 产出的镜像与 `serve`、`up`、`recreate` 实际选择的镜像一致。control 使用含 Node 24.22.3、DSH 0.2.2-rc.3 和策略插件的 ACP 镜像，desktop 与 egress 使用基础镜像。模型凭据只交给 control。
- 缺少 ACP 运行时、策略插件或模型凭据时，明确显示对应配置错误。回归验证上游 401 会显示模型连接错误并保留 owner 会话，owner 鉴权失败才触发重新登录。

**验收**需要记录实际运行的镜像和执行器，并从网页核对 ACP、模型和推理强度。启动配置应来自仓库和镜像，凭据由本地部署注入。

### A2 修复连续运行，再验收真实 ACP 文件任务

- 用受控夹具复现“页面显示任务结束，立即提交下一项却返回 409”。让任务状态与执行槽释放对齐。清理期间，界面应显示仍在收尾。确认可提交后，连续两项合法任务应能启动，真正并发时仍只允许一个活动 Run。
- A1 接通且连续运行回归通过后，提交两项仅使用工作区工具的任务。以固定资料验证真实模型读取、具体写入审批、生成文件、再次调用模型、产物下载及校验。审批的内容、目标和实际执行应一致。
- 用可控夹具覆盖拒绝、到期和审批期间文件变化，确认三种情况都不写入。逐轮核对用量，确认重复事件只结算一次，用量缺失时立即阻止后续模型派发。真实调用采用独立的限预算验收，日常回归使用本地替身。

**验收**需要同时证明可连续启动任务和真实文件工具闭环。验收记录应包括审批、文件校验与逐轮用量。

### A3 补齐租约失联保护，再验收真实桌面接管

- runner 自行判定 lease 到期并拒绝旧代次输入。控制连接丢失、过期后续租和重新连接均需覆盖。验证每次实际输入前都检查 lease，且在途和排队输入会在撤销或到期后停止。
- 接管时先撤权，再处理模型取消。执行端确认旧输入已停止后，界面才显示可以人工操作。无法确认时显示待核实。记录停止确认耗时以及已经提交、结果待核对的外部操作。
- A1、A2 和租约保护通过后，在同一套配置用真实 ACP 操作固定站点。显式授予桌面观察权限，核对截图、具体审批后的输入及页面结果。在模型请求中、待审批中和工具执行中验证取消与接管，随后检查旧审批、旧 lease 和延迟输入均已失效。

**验收**需要来自执行端的停止证据。网页和 AI 操作同一桌面，控制失联后的停止有可测上界，接管确认后没有旧任务输入。

### A4 在分离运行环境验证持久化与隔离

A2、A3 通过后，使用测试数据重新创建 control 和 desktop。核对已完成 Run、审批历史、用量、工作文件和浏览器配置。未完成的 Run 重启后应标为中断，旧审批失效，外部操作不自动重放。检查 ACP 子进程和临时目录的清理结果。

从实际容器角色核对 control 独占 owner 和模型凭据，runner 执行受服务端授权约束。应用鉴权入口是唯一发布的端口。用受控端点验证私有地址和 metadata 请求被拒，公共出站路径可用，Chromium 沙箱仍有效。

**验收**需要来自同一套 ACP 分离配置的重建记录和隔离结果，包括重建前后的文件、历史和值得保留的浏览器配置。

### A5 形成可复跑的基础 MVP 验收包

可以从 A1 开始整理夹具和探针，A1–A4 通过后再汇总验收。把旧脚本中依赖单容器的检查拆到控制面、桌面 runner 和 owner 客户端。桌面探针无需获得 owner 或模型凭据。记录操作步骤、实际结果、版本、架构、源码和镜像标识，分别列明本地夹具与真实模型任务各自验证的行为。[旧验收脚本](../scripts/verify-local.sh) · [桌面验证脚本](../scripts/verify-runtime.mjs)

**P1A 退出门槛**是在同一本地启动路径复现连续运行、真实 ACP 文件和桌面任务、审批拒绝、取消/接管、租约到期、同卷重建及运行时隔离。通过后即可进入 P1B。

## 5. P1B：最小差异化版本——可靠的双向交接

依赖 P1A，优先落实差异化文档的第 3、4、6、9 点。把工作状态、执行尝试、桌面输入权和观察权限分别记录。

### B1 区分暂停交接与取消

用户可以要求暂停并接手，AI 也可以在需要人工操作时请求交接。沿用 A3 的撤权和停止确认。控制器先撤权、废止审批并停止派发，再从执行记录生成事实说明。说明包括目标、已完成步骤、已有产物、尚未执行和结果待核对的动作。取消结束本次执行。暂停则保留工作记录，供用户重新委派。

### B2 关闭 AI 的观察通道

依赖 B1。进入私人操作时，取消旧输入权并撤销当前观察授权。检查覆盖截图、页面读取、工作区和下载读取、工具结果转发和观测记录。在读取、结果转发及下一次模型派发前核对授权与代次。丢弃撤权后才返回的旧结果及尚未发给模型的旧观察数据。

用户仍可通过 owner 界面查看和操作桌面。进入私人操作前已经发给模型的数据无法收回。只有用户主动选择新的观察范围后，AI 才可重新观察。后续接入剪贴板、录制等能力时也要通过相同检查。

### B3 在新状态和新授权下重新委派

依赖 B1、B2。用户补充说明后，创建与同一项工作关联的新 Run 和 ACP session。核对目标、账号/页面、文件版本、观察范围及累计预算。先在新授权范围内观察，再取得新的输入 lease。按控制代次废止旧坐标、元素引用和审批，记录用户已完成的步骤。

工作记录累计展示多个 Run 的用量和剩余预算。上次用量无法结算时先核对，新增预算需由用户明确授权。若已有外部提交结果待核对，先确认其状态，再决定下一步。

### B4 用固定场景验收完整交接

用测试站点模拟需要人工的步骤。AI 先生成部分资料，用户在私人操作中改变页面或文件，再选择开放范围并重新委派。验收记录要能追溯新观察、新审批、新 lease 和最终产物。用合成数据覆盖登录类场景。

**P1B 退出门槛**包括网页上的完整往返交接。对每条已接通的观察通道验证正常读取、关闭后阻断、晚到结果丢弃和用户主动重新开放。回归旧输入、旧审批和旧引用失效，验证双标签竞争时同一时刻只接受一个输入者，断线后旧 lease 到期。移动端交接和通知按 P2B 的实际需求排期。

## 6. P2A：文件可验收，工作可恢复

依赖 P1B，在交付真实重要资料前完成差异化文档第 2、7 点及持久性承诺。

- **待验收区与产物清单**：新产物先暂存，展示位置、校验值、来源、结果、用量和未完成项；不靠完整截图/私密内容留存换取审计。
- **差异与选择性接受**：展示每个文件新增/修改/删除，允许逐个接受；合并时重新检查原文件版本，用户并发修改时拒绝覆盖并保留两侧结果。
- **修改前恢复点**：接受或覆盖前保存必要的本地原版本；恢复同样受授权与版本检查。清楚说明恢复会影响哪些文件，外部提交不随本地回滚撤销。
- **可重建环境**：区分工作文件、浏览器/应用配置、声明式安装清单、控制状态和临时数据。仅承诺经验证的文件保留与必要配置恢复，不承诺进程继续或内存级休眠。
- **独立备份与恢复**：备份离开原数据卷，包含必要一致性标记、版本、校验和及密钥保管方案；浏览器 profile 先停用或按一致性规则处理。在另一干净本地实例/VM 实际恢复并完成新任务。相同主机的恢复演练只证明恢复流程，不证明跨主机灾备；对外承诺跨机恢复前还必须在第二台机器验证。

**P2A 退出门槛**：用户可只接受部分文件，冲突不丢数据，恢复点可还原，独立备份能在干净环境恢复；资料、历史和必要配置可核对，失效登录由用户重新认证。

## 7. P2B：减少重复确认，进入个人日常 beta

依赖 P2A，再落实差异化文档第 5、8 点。

1. 增加可撤销、到期失效的有限任务授权，分别表达“看、改、带出去、使用账号、花资源”。先覆盖服务端可验证的文件和受限流程；无法可靠约束的通用 GUI 继续逐项确认。
2. 授权绑定具体资源、目录/站点、账号、有效期及预算。接管、对象变化或权限过期后重新核对，不做无边界自动批准。
3. 增加待我处理的任务箱：登录、审批、验收、用量不明、故障和备份待办。关闭网页时按用户事先选择的继续/到确认点暂停/停止规则执行，不能因断线扩大权限。
4. 成功流程可保存为模板，但每次运行重新授权。稳定后再按真实需求增加跨设备通知与控制；通知不能批准过期动作。
5. 完成连续 7 天个人使用及磁盘不足、模型超时、控制/runner 崩溃、更新失败的演练。显示已报告 tokens 与未核实用量，没有可靠单价时不编造金额。

**P2B 退出门槛**：常用任务减少重复审批，仍能解释授权范围、随时撤销和私人接管；无不可恢复的资料丢失，失败有明确处置入口。

## 8. P3–P5：部署、开源与后续扩展

### P3：可恢复的私人部署 v1

依赖 P2。届时另行确认服务器与预算，先验证通用 amd64 Linux VM/VPS，再按实际机器验证 OCI/arm64；未经实机测试的架构保持未认证。本地开发不等待免费实例配额。

交付一条可复跑的安装、健康检查、备份、恢复、升级和保留/删除数据的卸载路径。配置私网或 TLS、强身份验证、最小暴露端口、独立备份与版本回退规则；在第二台干净机器恢复并完成新任务，再让未参与开发的人按文档部署。

发布固定版本与镜像标识、支持矩阵、脱敏验收清单、第三方许可证/SBOM、安全报告入口和数据导出说明。届时复核[Oracle 可行性研究](research/oracle-cloud-feasibility.md)及供应商实际条款，不把历史免费额度视为长期保证。通过后再宣传“私人云电脑部署范式”。

### P4：可信团队与多台电脑

出现真实需求后再引入成熟身份接入、角色权限、数据库/worker 演进、资源配额、会话路由和多计算机调度。同一桌面始终只有一个有效输入者；不同租户运行任意任务前须有独立 VM 或经验证的隔离边界，不能把单 owner Compose 的复制视为多租户认证。

### P5：生态与专门能力

多 Agent/执行器、连接器与扩展、定时任务、实验电脑、更多模型、WebRTC/音视频、Windows/GPU、托管计费按需求进入。每个新增入口都必须遵守相同的授权、观察、交接和恢复规则；不以此阻塞个人版。

## 9. 当前可直接执行的开发顺序

1. **现在并行。** A1 对齐 ACP 镜像和默认启动入口。A2 复现并修复连续任务 409。A3 实现 runner 租约到期和停止确认。同步准备 A4、A5 所需的夹具与探针。
2. **先验收文件，再验收桌面。** 启动和连续运行稳定后，先验证真实 ACP 文件任务，便于单独排查工具桥、审批与用量。随后加入桌面和撤权场景，验证旧输入在控制失联或接管后确实停止。
3. **在同一套配置收口 P1A。** 重建 control 和 desktop，实测状态保留及隔离，提交带运行版本和复跑方式的验收记录。
4. **通过 P1A 后进入 B1 → B2 → B3 → B4。** 先做暂停与事实交接，再接通观察撤销、重新委派及完整演示。
5. **通过 P1B 后进入 P2A → P2B → P3。** 先让用户能验收和恢复文件，再扩大有限授权，最后验收私人部署。

## 10. 验收和文档约定

每项验收记录环境/版本、前置数据、操作、预期与实际、产物或安全元数据、已知缺口及复跑方式。每条核心产品场景先建立固定夹具，再多次重复；没有足够样本时不宣称稳定成功率。接管耗时、资源和网络目标依据实际测量再定，原建议阈值不是已达标结果。

本地代码回归使用已验收的 Node 24 解释器执行：

```bash
node scripts/check.mjs
node --test apps/control/test/*.test.mjs apps/desktop/test/*.test.mjs
```

这些命令不调用真实模型。[真实 ACP 文本检查](../scripts/verify-acp-host.mjs)需要显式 `--live`，只验证适配器文本与用量，不代替 A2–A5；真实付费任务只在明确的本地验收操作中执行。本次路线调整未重新调用供应商。
